# SoundFit — 개인화 AI 음악 스튜디오 프로토타입

*Personalized AI Music Platform PRD v1.0* 의 가장 위험한 주장들을, 상용 음악 API 계약 **전에**
검증하기 위해 만든 **동작하는** 프로토타입입니다. 서버가 없고, 빌드 단계가 없으며,
오디오 파일을 하나도 포함하지 않습니다. 소리는 브라우저의 Web Audio로 직접 합성합니다.

- 랜딩: `index.html`
- 스튜디오(7단계 전체 여정): `studio.html`
- Music DNA 대시보드: `dna.html`
- 스펙 변경 문서: [`docs/SPEC-v1.1-delta.md`](docs/SPEC-v1.1-delta.md)

## 왜 이렇게 만들었나

PRD v1.0에서 구현해 보기 전까지는 참/거짓을 알 수 없는 주장이 몇 개 있었습니다.

- "수정은 국소적이어야 한다" — 실제로 후렴만 다시 만들 수 있는가?
- "통제된 차이를 가진 두 버전" — 무엇을 통제하는가? 차이를 설명할 수 있는가?
- "금지 항목"과 "민감 정보 분류" — 경고인가, 실제 차단인가?
- "유료 요청은 멱등해야 한다" — 상태 기계와 어떻게 맞물리는가?

프로바이더를 고르기 전에 이걸 먼저 확인해야 순서가 맞습니다. 프로바이더 품질은
나중에 바꿀 수 있지만, 위 구조를 잘못 잡으면 전부 다시 씁니다.

## 실행

정적 파일이지만 ES 모듈을 쓰기 때문에 `file://`로는 열 수 없습니다.

```bash
# 저장소 루트에서
python3 -m http.server 8099
# http://localhost:8099/soundfit/ 접속
```

로직 테스트(브라우저 불필요, 의존성 없음):

```bash
cd soundfit
node tests/logic.test.mjs      # 57 passed
```

데이터는 전부 `localStorage`에 있습니다. 초기화는 브라우저 저장소를 지우거나
Music DNA 대시보드의 "전체 초기화"를 쓰세요.

## 시뮬레이션이거나 의도적으로 넣지 않은 것

정직하게 적어둡니다. 이 목록을 오해하면 잘못된 판단을 하게 됩니다.

- **음악 품질** — 절차적 합성입니다. 상용 생성 모델의 대체물이 **아닙니다**.
- **보컬** — 포먼트 필터로 만든 합성 **가이드 보컬**입니다. 사람의 노래가 아니고,
  어떤 실제 인물의 목소리도 복제하지 않습니다.
- **가사** — 언어 모델이 아니라 템플릿 엔진입니다. 검증 대상은 문장 품질이 아니라
  **편집·승인·차단·측정 워크플로**와 교체 가능한 어댑터 경계입니다.
- **유사도 검사** — 멜로디 인터벌 n-gram 기반 상징적 검사입니다. 오디오 지문이 아니고,
  참조 세트는 공개 도메인 전래 멜로디(테스트 픽스처)입니다.
- **결제** — 확인 대화상자로 시뮬레이션합니다. PG 연동은 없습니다.
- **MP3** — 일부러 넣지 않았습니다. 인코딩은 배포용 마스터링 서비스의 역할이고,
  프로바이더가 실제 지원하는 포맷만 제공해야 합니다(capability registry).
- **공유 링크** — 만든 브라우저에서만 열립니다. 실제로는 만료 시간이 있는 서명된 URL입니다.
- **저장소·암호화·다중 사용자** — 전부 없습니다. `localStorage`뿐입니다.

## 성능

샌드박스 컨테이너 실측: 190초 곡 = 10구간 / 노트 2,167개 / 렌더 **약 28초**(약 6.7배속).
일반 노트북에서는 더 빠릅니다. 다만 실제 서비스의 체감 지연은 **프로바이더 API가
결정**하므로 이 수치를 제품 지표로 쓰면 안 됩니다.

렌더 최적화 과정에서 배운 것: 오프라인 렌더 비용은 컨볼루션 리버브가 아니라
**노트당 오실레이터·BufferSource 개수**가 지배합니다. 리버브를 Schroeder 콤 네트워크로
바꿔봤지만 속도 이득이 없어(레벨만 망가져서) 컨볼루션으로 되돌렸습니다.

## 코드 구조

```
soundfit/
  index.html  studio.html  dna.html  share.html
  assets/js/
    audio/       theory · arranger · instruments · renderer · wav · fingerprint
    domain/      dna · story · lyrics · spec · rights · capability
    core/        store (상태 기계 · 이벤트 · 멱등성 · 원가 원장 · 감사)
    ui/          dom · player · engpanel · lyriccard
    studio.js  landing.js  dna-page.js  share-page.js
  tests/logic.test.mjs
  docs/        SPEC-v1.1-delta.md · event-taxonomy.md · capability-registry.md
```

`audio/arranger.js`와 `domain/*`는 DOM·Web Audio 의존이 없는 순수 모듈입니다.
그래서 Node에서 그대로 테스트할 수 있고, 실제 백엔드(NestJS/FastAPI)로 옮길 때
**그대로 이식 가능한 부분**이기도 합니다.

## 프로바이더로 교체할 때

`domain/capability.js`에 실제 프로바이더 엔트리를 추가하고, `ACTIVE_ADAPTERS`에서
`MusicGenerationAdapter`를 바꾸면 됩니다. 다만 준비 게이트 6개 필드가
**계약서 기준으로** 채워지지 않으면 `readinessGate()`가 유료 라우팅을 거부합니다.
그게 의도된 동작입니다.

`sectionRevision`이 `false`인 프로바이더로 바꾸면, 수정 요청은 자동으로
전체 재생성으로 폴백되고 사용자에게 이유와 예상 시간이 고지됩니다.
